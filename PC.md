# Общая картина: зачем вообще железо

Любая программа — это набор инструкций + данные. Чтобы их выполнить, нужно:

1. Где-то считать (CPU).
2. Где-то хранить данные во время работы (RAM).
3. Где-то хранить данные постоянно (диск/SSD).
4. Как-то всё это соединить (шины, чипсет).
5. Как-то показать результат (GPU → монитор) и принять ввод (периферия).

Ключевая идея: иерархия памяти — чем ближе к CPU, тем быстрее и дороже, но меньше по объёму.

```text
Регистры CPU (байты) → L1/L2/L3 кэш (КБ–МБ) → RAM (ГБ) → SSD/HDD (ТБ) → сеть/облако
   быстрее, дороже  ←──────────────────────────────────→  медленнее, дешевле
```

## CPU (процессор)

По-простому: мозг ПК. Исполняет инструкции программ.

### Из чего состоит CPU

| Компонент               | Что это                                                                                                                       |
|-------------------------|-------------------------------------------------------------------------------------------------------------------------------|
| **Ядра (cores)**        | Независимые исполнители. 8 ядер = 8 потоков инструкций параллельно (физически).                                               |
| **Потоки (threads)**    | Hyper-Threading/SMT позволяет одному ядру держать 2 потока, переключаясь между ними, когда один ждёт память. Это не удвоение мощности, а заполнение пауз. |
| **Регистры**            | Сверхбыстрая память внутри ядра (несколько десятков штук). Там живут текущие операнды.                                         |
| **Кэш L1/L2/L3**        | Буфер между ядром и RAM. L1 самый быстрый и маленький (десятки КБ), L3 — общий для всех ядер (МБ).                              |
| **ALU (арифметико-логическое устройство)** | Делает математику и логику.                                                                      |
| **Контроллер памяти**   | Современные CPU общаются с RAM напрямую (у Intel — через чипсет частично, у AMD Ryzen — встроен).                             |

**DevOps:**

- `load average` в Linux — сколько процессов ждут CPU (включая ожидание I/O!).
- `%sy` vs `%us` — время в ядре vs в пользовательских программах.
- Число ядер влияет на то, сколько контейнеров/процессов реально параллелятся.

## RAM (оперативная память)

По-простому: быстрый «стол», на котором лежат данные работающих программ. Выключил питание — всё стёрлось.

**Как работает:**

- Массив ячеек, каждая с адресом.
- CPU обращается по адресу → получает байты.
- Работает синхронно с тактовой частотой (DDR4/DDR5 — удвоенная передача за такт).
- **Виртуальная память:** каждая программа думает, что у неё есть всё адресное пространство. MMU (Memory Management Unit) в CPU транслирует виртуальные адреса в физические через таблицы страниц.
- Страницы (обычно 4 КБ) — единица трансляции и свопинга.
- **Swap** — когда RAM кончается, ядро выгружает страницы на диск. Медленно, но спасает от OOM.

**DevOps:**

- **free -h** — смотри не на «free», а на **available** (сколько реально можно отдать).
- Page cache — файлы, закэшированные в RAM. Это не «занятая» память, её можно освободить.
- OOM Killer — ядро убивает процесс, если память кончилась.
- В контейнерах лимиты по памяти → cgroup.

## Накопители: HDD vs SSD

**HDD (жёсткий диск):**
- Магнитные пластины, вращаются, головка читает/пишет.
- Медленный (~100–200 МБ/с, задержка ~5–10 мс).
- Дёшево, много объёма.

**SSD (твердотельный):**
- Флеш-память (NAND), нет движущихся частей.
- Быстрый (500 МБ/с – 7 ГБ/с у NVMe, задержка ~0.1 мс).
- Ограничен ресурс записи (ячейки изнашиваются)

**DevOps:**

- `iostat`, `iotop` — смотреть IOPS и задержки.
- На облачных дисках IOPS часто лимитированы → узкое место БД.
- `fsync` — сброс на диск, критично для БД (Postgres, etcd).

## GPU (видеокарта)

По-простому: много маленьких ядер, заточенных под параллельные вычисления (графика, ML).

**Из чего состоит:**

- **Ядра** (штуки-тысячи) — простые, но их много.
- **Видеопамять** (VRAM) — отдельная память на карте, быстрая (GDDR6/HBM). Не путать с RAM!
- **Конвейеры** — текстуры, растеризация, шейдеры.

## Чипсет и шины

Чипсет (chipset) — «коммутатор» между CPU и периферией (USB, SATA, сеть, часть PCIe).

Шины:
- **PCIe** — основная шина для GPU, NVMe, сетевых карт. Линии (lanes) x1/x4/x16.
- **DMI** (Intel) / Infinity Fabric (AMD) — связь CPU ↔ чипсет.
- **USB, SATA, Thunderbolt** — периферия.

## Как всё это взаимодействует (сквозной пример)

Ты запускаешь `python app.py`:

1. **CPU** с диска загружает бинарник Python в **RAM** (через page cache).
2. Интерпретатор читает инструкции, **CPU** исполняет.
3. Данные из **RAM** подгружаются в **L1/L2/L3 кэш** по мере надобности.
4. Если нужно прочитать файл — идёт запрос к **SSD/NVMe** через **PCIe**.
5. Если нужно отправить данные в сеть — **NIC** через **PCIe + DMA** в **RAM**.
6. Если нужно посчитать матрицы — данные копируются в **VRAM GPU**.
7. Результат — обратно в **RAM** → на экран через **GPU**.

> **Узкое место всегда там, где медленнее всего.** Обычно это диск или сеть, реже — RAM, ещё реже — CPU.

## Шпаргалка

| Термин        | Что это                                                       |
|---------------|---------------------------------------------------------------|
| **Ядро CPU**  | Независимый исполнитель инструкций                            |
| **Поток**     | Логический исполнитель на ядре (SMT)                          |
| **Кэш L1/L2/L3** | Быстрая память между ядром и RAM                           |
| **RAM**       | Энергозависимая оперативная память                            |
| **VRAM**      | Память на GPU                                                 |
| **Swap**      | Выгрузка страниц RAM на диск                                  |
| **Page cache**| Кэш файлов в RAM                                              |
| **MMU**       | Трансляция виртуальных адресов                                |
| **IOPS**      | Операций ввода-вывода в секунду                               |
| **PCIe**      | Шина для GPU, NVMe, NIC                                       |
| **DMA**       | Прямой доступ устройств к RAM                                 |
| **NUMA**      | Неоднородный доступ к памяти (важно для многопроцессорных серверов) |
